# SwiftUI 蘋果風格手感指南

> 一句話：系統元件的手感 Apple 已經調好了，別動；自己補的地方，也用蘋果自己的語彙去補，不要另外發明一套。
>
> 寫於 2026-11。標註的 iOS 版本與 API 以當時為準，WWDC 之後可能會變。

---

## 一、預設就好，別動

使用者的手感期待就是這些元件養出來的，改了反而怪。

| # | 元件 | 預設已經有的 | 怎麼做 |
|---|---|---|---|
| 1 | `Button` | 按下變淡、放開恢復 | 直接用；要換樣式用 `ButtonStyle`，別拿掉按壓狀態 |
| 2 | `NavigationStack` | 推入、返回、左緣滑回（可中途放棄） | 別自己做返回手勢，也別蓋掉左緣滑回 |
| 3 | `sheet` | 彈出、下拉關閉、半高停靠（`presentationDetents`） | 要防誤關用 `interactiveDismissDisabled`，別重寫 |
| 4 | `List` | 慣性捲動、回彈、`swipeActions`、長按 `contextMenu` | 清單畫面盡量用 `List`，自己用 `ScrollView` 拼會少很多東西 |
| 5 | `TabView` | 切換、點兩下回頂端 | 別在分頁切換加自訂動畫 |
| 6 | `Toggle`、`Picker`、`DatePicker` | 外觀、動畫、部分觸覺回饋 | 不用再加震動，加了會重複 |
| 7 | 鍵盤避讓 | 鍵盤彈出時自動讓位 | 版面被擠爆才處理，通常用 `ScrollView` 包起來就好 |

## 二、一定要自己補

SwiftUI 預設不會幫你做，不補就會覺得「卡卡的、沒反應」。

### 8. 自己做的可點元件沒有按壓狀態

用 `.onTapGesture` 做的卡片，按下去完全沒變化，也沒有無障礙。改用 `Button` 包起來，加自訂 `ButtonStyle`：

```swift
struct PressStyle: ButtonStyle {
    func makeBody(configuration: Configuration) -> some View {
        configuration.label
            .scaleEffect(configuration.isPressed ? 0.96 : 1)
            .opacity(configuration.isPressed ? 0.85 : 1)
            .animation(.snappy, value: configuration.isPressed)
    }
}

// 用法
Button { open(note) } label: { NoteCard(note) }
    .buttonStyle(PressStyle())
```

### 9. 觸覺回饋（iOS 17+）

大部分動作預設不會震。只放在有意義的時刻：完成、錯誤、吸附對齊、刪除。每顆按鈕都震，震動就沒意義了。

```swift
Button("儲存") { save() }
    .sensoryFeedback(.success, trigger: savedCount)

// 錯誤時
.sensoryFeedback(.error, trigger: errorCount)
```

### 10. 資料變化的動畫

新增、刪除、排序、展開收合，預設是瞬間切換，使用者看不出發生了什麼。

```swift
withAnimation(.snappy) {
    notes.remove(at: index)
}

// 或綁在某個值上
.animation(.smooth, value: isExpanded)
```

### 11. 數字變化的過渡（iOS 17+）

金額、計數換值時預設直接跳。記帳、計數類 app 加這個很有感。

```swift
Text("\(count) 則")
    .contentTransition(.numericText(value: Double(count)))
    .animation(.snappy, value: count)
```

### 12. 載入中、空的、出錯三種狀態（iOS 17+）

預設只會顯示一片空白。三種都要畫：`ProgressView`、`ContentUnavailableView`、出錯時說明怎麼辦。

```swift
if notes.isEmpty {
    ContentUnavailableView("還沒有筆記",
        systemImage: "note.text",
        description: Text("點右下角的 + 開始寫"))
}
```

### 13. 「減少動態效果」設定

使用者在系統設定開了這個選項，你的縮放、位移動畫照樣跑。開啟時把位移縮放換成淡入淡出：

```swift
@Environment(\.accessibilityReduceMotion) var reduceMotion

.transition(reduceMotion ? .opacity : .scale.combined(with: .opacity))
```

### 14. 自訂手勢拖動時的回饋

自己寫的 `DragGesture`、長按，預設拖著沒有視覺變化，放手直接跳位。拖動中要跟手（位置即時更新），可以稍微放大或加陰影，放手用 spring 回位。

## 三、看 app 類型再調

工具型（記帳、筆記、月曆）通常不用碰；手感型（史萊姆、遊戲）的產品就是這些。

| # | 項目 | 工具型 | 手感型 |
|---|---|---|---|
| 15 | 自訂轉場（卡片展開成全頁） | 用一兩處就好 | 可以多用 |
| 16 | spring 參數（`duration`、`bounce`） | 用預設 `.snappy`／`.smooth` | 列參數表，真機一格一格試 |
| 17 | 手勢物理（跟手、放手速度、橡皮筋阻尼） | 不用 | 核心，一定要做 |
| 18 | 自訂震動樣式（Core Haptics） | 不用 | 要做「捏下去的質感」這種連續震動才用 |
| 19 | 裝飾動畫（粒子、慶祝） | 盡量不要 | 只在完成的瞬間，短、不擋操作 |

卡片放大成全頁的轉場（`zoom` 需 iOS 18+）：

```swift
NavigationLink(value: note) { NoteCard(note) }
    .matchedTransitionSource(id: note.id, in: ns)

// 詳情頁
NoteDetail(note)
    .navigationTransition(.zoom(sourceID: note.id, in: ns))
```

## 四、自己補的也要像蘋果：四步

### 步驟 1：只用系統內建的語彙

| 要補的 | 用系統的這個 | 不要這樣做 |
|---|---|---|
| 動畫曲線 | `.snappy`（按壓、小變化）、`.smooth`（轉場）、`.bouncy`（俏皮的時刻） | 自己寫 `.easeInOut(duration: 0.5)` |
| 震動 | `.sensoryFeedback` 照意義挑：`.selection`、`.success`、`.error`、`.impact(weight: .light)` | 全部用同一種強震 |
| 圖示動態 | SF Symbols 加 `.symbolEffect(.bounce)`、`.contentTransition(.symbolEffect(.replace))` | 自己畫圖示再做動畫 |
| 浮層、底板 | `.regularMaterial`、`.ultraThinMaterial`（毛玻璃） | 半透明黑色色塊 |
| 字 | `.font(.title)`、`.body` 這類內建字級 | 寫死 17pt |
| 圓角 | `RoundedRectangle(cornerRadius: 16, style: .continuous)` | 一般圓角（轉角的弧線會比較生硬） |
| 間距 | `.padding()` 預設值、`List` 的內建間距 | 每個畫面各寫各的數字 |

光這一步就能做到七八成像。

### 步驟 2：照蘋果的動作原則調整

- **跟手**：手指拖到哪，東西就在哪，不能延遲。
- **可以中斷**：動畫播到一半手指碰到，要馬上接手，不是等它播完。
- **從哪來回哪去**：卡片放大成全頁，關掉時要縮回原本那張卡片，不是直接消失。
- **克制**：按下縮到 0.96 左右就好，回彈只要一點點。蘋果介面裡的動畫多半短到你不會特別注意。
- **只做回饋，少做裝飾**：動畫的工作是告訴使用者「收到了」「東西去哪了」，不是表演。

### 步驟 3：每一項都找一個蘋果自家 app 當範本

| 要做的 | 去看哪個 app |
|---|---|
| 卡片展開成全頁 | App Store「Today」分頁、照片 |
| 數字變化 | 計算機、健身、時鐘的計時器 |
| 空狀態 | 備忘錄、提醒事項清單空掉時 |
| 刪除、新增的動畫 | 提醒事項、Wallet |
| 拖曳排序 | 主畫面拖圖示、提醒事項 |
| 完成的慶祝 | 健身圓環合起來那一刻 |

看的方法：

1. 用 iPhone 螢幕錄影，把蘋果 app 的同一個動作錄下來。
2. 慢放、逐格看：多快開始動、彈了幾下、什麼時候震。
3. 錄自己 app 的同一個動作，兩段並排比較。

### 步驟 4：寫成「動作代號表」交給 Claude Code

最容易破功的是每個畫面寫的動畫和震動都不一樣，越做越不統一。先定一張表，之後每次叫 Claude Code 寫畫面都附上：

| 情境 | 動畫 | 震動 | 其他 |
|---|---|---|---|
| 按壓可點元件 | `.snappy`，縮到 0.96 | 無 | 用 `PressStyle` |
| 切換選項 | `.snappy` | `.selection` | |
| 完成一件事 | `.bouncy` | `.success` | SF Symbol `.symbolEffect(.bounce)` |
| 出錯 | 無位移 | `.error` | 文字說明怎麼辦 |
| 刪除 | `.snappy` | `.impact(weight: .light)` | |
| 頁面轉場 | `.smooth` | 無 | 卡片來源用 `zoom` |
| 數字變化 | `.snappy` | 無 | `.numericText` |
| 減少動態效果開啟時 | 全部改淡入淡出 | 照舊 | |

（以上是起始範例，依各 app 調整。）

也可以把它寫成程式碼，讓畫面只能從這裡取值：

```swift
enum Motion {
    static let press = Animation.snappy
    static let change = Animation.snappy
    static let transition = Animation.smooth
    static let celebrate = Animation.bouncy
    static let pressScale: CGFloat = 0.96
}
```

## 五、驗收

- **一定要用真機判斷**：模擬器的延遲和掉幀都不準。
- **用最舊的機型跑一次**：拿你支援的最舊 iPhone，開低電量模式再跑一次。
- **和蘋果 app 並排比較**：自己的錄影和蘋果 app 的錄影放在一起看。
